# 下一步：NPC 层设计

2026-10-02 更新。Minecraft 已接入人格、检索、独立持久记忆、pi 工具循环和事件调度。下一步重点是四人格真实世界实验、行为质量和跨运行边界，不再是从零接通组件。

## 已确定的方向

- 模型运行采用 pi 的可嵌入能力，Anima 在其外部组织人格、记忆与决策。
- 人格与长期记忆归 NPC 模块管理，世界通过共享协议交互。
- 第一版使用有限动作和有界的思考流程。
- 每个 NPC 使用独立的私有上下文，保持统一的初始身份设定。
- 已有公开影视角色材料和本地人格档案；公开演示继续使用这些材料，私人微信／QQ 数据及其衍生档案留在本地。
- 当前世界选择 Minecraft，NPC 的实际说话与行动通过 Mineflayer 执行；文字会客室保留用于调试。

## 已完成的整合

1. **模型入口**：本地 CLIProxyAPI 已通过实际 pi 工具调用检查。其他环境仍需自行配置接口与密钥。
2. **人格上下文**：`world-persona.ts` 读取本地人格与原作事实，`world-agent.ts` 使用游戏专用提示、统一身份和证据检索，不直接套用文字会客室整段提示。
3. **身体接口**：`WorldAgentPort` 通过观察、执行和公开场景资料接入 Minecraft；`record.name` 作为当前 NPC ID。原生执行不加载 Pathfinder／Viewer。
4. **记忆连续性**：`WorldMemory` 按 NPC/roleId 追加 JSONL，区分事实回执、听说和意图，按来源去重并在重启后恢复。
5. **有限唤醒**：`NpcScheduler` 合并事件，最多四人并发但每人串行，限制聊天互相唤醒并在错误后退避。自己的动作结果不再额外唤醒自己。
6. **预算与取消**：每次决策最多 6 个行动、8 轮调用、90 秒，工具和上下文有大小限制；停止时取消任务与身体控制。

## 接下来的验证与设计

1. **完整生存与执行一致性**：先观察采集、合成、食物、分工和探索，再逐步观察下界与末地战斗。行动回执必须反映实际背包、位置、生命等变化，角色自述不能代替世界结果。
2. **人格是否影响决策**：同一公开观察下比较四人的说话、分工、风险偏好与失败后的调整；避免只剩口头禅不同。
3. **记忆是否可靠**：检查离开后重逢、任务中断重启、他人说法与亲历事实的区别，以及模型是否把计划当作成功经历。
4. **不同实验的隔离**：当前记忆已按 worldId/NPC/roleId 续用。继续验证恢复存档、独立新世界和旧实验之间的位置、计划与经历不会混用。
5. **正式共享接口**：将目前 port 与动作 schema 整理成 `protocol` 契约；再考虑持久队列、游标与跨重启重复动作处理。
6. **实际效果与费用**：记录成功动作比例、循环卡住原因、延迟和 token 消耗，再决定是否增加反思、向量检索或更复杂的规划。

## 当前验证场景

当前使用谢耳朵、福尔摩斯、死侍、胡一菲进行 [完整生存实验](minecraft-survival.md)。四人在随机主世界空手出生，自主合作获取资源、探索下界和末地、尝试击败末影龙。旧的直接进入末地场景只作身体工具诊断，不能计作完整目标。全流程胜利结果待实测。

同时保留更简单的对照场景：两人相遇、交谈、分开与再次见面，再加入一个远处角色验证信息隔离。第一阶段仍不引入经济系统或复杂资源争夺。
