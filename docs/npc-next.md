# 下一步：NPC 层设计

本文用于下一轮共同设计。下列事项尚未转成具体类型、实现或依赖选型。

## 已确定的方向

- 模型运行采用 pi 的可嵌入能力，Anima 在其外部组织人格、记忆与决策。
- 人格与长期记忆归 NPC 模块管理，世界通过共享协议交互。
- 第一版使用有限动作和有界的思考流程。
- 每个 NPC 使用独立的私有上下文，保持统一的初始身份设定。
- 人格提取可从已有微信、QQ 数据开始；当前尚未进行模型提取。

## 建议讨论顺序

1. **一个 NPC 由什么组成**：人格档案、初始经历、私有身份、关系认知、当前目标、运行实例分别如何表示。
2. **记忆怎样组织**：原始证据、事件、信念、约定和反思怎样存储、检索与更新。
3. **一次思考怎样运行**：什么时候唤醒、构建多少上下文、调用几轮模型、何时交回控制权。
4. **怎样封装 pi**：NPC 核心需要哪些模型接口，pi 可以提供哪些受限工具。
5. **怎样检验效果**：人格相似度、记忆连续性、私有信息隔离、行动一致性、延迟与调用费用。

## 首个验证场景

拟使用一个由本人材料构建的角色和两个虚构角色。先在文字场景里完成相遇、交谈、分开与再次见面，确认约定和个人认识能够延续，再接入图形世界。

具体实现应在上述职责和接口讨论清楚后展开。
