# 行动吞吐优化与对照实验

这一版继续使用 pi 大脑、正式 `NpcScheduler` 和独立身体控制器，重点减少首次行动前的模型往返、无收益的提前规划，以及条件未改变时的失败重试。它不把技能启动次数或重复按键当作有效进展。

## 优化内容

| 改动 | 行为与边界 |
| --- | --- |
| 尽早提交可执行计划 | 本轮观察和最新身体状态已在上下文中；信息足够时可直接 `body_plan`，无需固定先 `observe` 再 `remember`。信息缺失时仍可查询。 |
| 计划附带记忆 | `body_plan`、`body_append` 可以附带可选的目标、计划记忆；授权接收后再保存，避免为记忆工具额外等待一次模型。记忆保存失败会明确报告，不把已启动动作撤回。 |
| 按时间提前规划 | 身体提供 `remainingWorkMs` 估计；规划提前量参考最近真正产出可执行计划的耗时。估计用于提示，不是完成时间保证。 |
| 标记完整有限任务 | 只有任务明确没有后续工作、队列覆盖整项任务时才使用 `terminal: true`。若后续工作稍后公布，当前已知部分排完也必须是 `false`。它不宣告成功，也不关闭自保、失败反馈或授权到期处理。 |
| 当前思考轮接收新消息 | 自己听到的新消息合并送入下一次模型决策，无需等待下一次调度。消息保留说话者、作为未核实的环境材料；数量和续接批次有上限，不中断身体、不增加原有执行预算。 |
| 失败有界 | 缺材料、没有可见资源、候选耗尽等明确失败交回规划；不明原因且持续无进展的尝试也有次数上限。撤退耗尽授权距离后不再原地反复启动，其他仍有效的自保授权可以继续。 |
| 采集局部恢复 | 原生采集可以在有限候选和移动预算内尝试其他已观察目标，保留任务范围和进度。预算耗尽是本次尝试失败，不等于整个世界不存在资源或路径。 |

修改计划仍要求使用本次请求实际观察到的版本。追加保留当前技能、进度与累计预算；停止、取消、过期或阻塞的授权不能被追加复活。

## 如何验证

```powershell
npm run test:efficiency

npm run minecraft:efficiency

npm run minecraft:efficiency -- --run --mode=agent --variant=baseline --task=route
npm run minecraft:efficiency -- --run --mode=agent --variant=optimized --task=route

npm run minecraft:efficiency -- --run --mode=agent --variant=baseline --task=material
npm run minecraft:efficiency -- --run --mode=agent --variant=optimized --task=material

npm run minecraft:efficiency -- --run --mode=agent --variant=baseline --task=continuation
npm run minecraft:efficiency -- --run --mode=agent --variant=optimized --task=continuation
```

没有 `--run` 只显示帮助，不连接游戏或调用模型。真实 Agent 默认使用 `gpt-6.1-sol`，两组都允许完整规划最多 12 步，没有人为延迟或强制分批。可用 `--repeat=2` 重复；正式比较应交替运行两组并保留失败样本。

| 题目 | 公开任务与成功证据 |
| --- | --- |
| `route` | 一开始公布六个路点。服务器确认按序经过并在末点落稳，观察首次计划耗时、接续空档和多余请求。 |
| `material` | 夹具先执行一份缺材料的旧合成计划。任务公开允许缺料后改去会合地点；必须观察到真实合成失败和服务器确认到达。只测试失败恢复，不把播种的旧计划算作模型决策。 |
| `continuation` | 起初只公布三个路点；服务器确认首个路点且身体仍在执行时，通过公开消息发布后续工作。检查六个路点的实际完成，后续坐标不会提前送给模型。 |

离线机制测试另覆盖缺料、资源不可见、候选耗尽、撤退距离上限、保留独立自保、追加不打断、时间提前量和 terminal 提示。它们使用可控执行回执验证生产控制器，不能冒充真实服务器或模型成绩。`--mode=scripted` 同样只是机制诊断，其每批两步和人工规划延迟必须与真实 Agent 结果分开解释。

## 对照与隔离边界

两组使用同一份源码、模型、公开目标和原生执行器，均开启上一版的连续执行、快速调度和失败中断。`baseline` 关闭本版 `throughputOptimizations`，`optimized` 开启它。原生采集恢复与结构化错误等基础修复两组共享，所以这是当前源码的功能开关对照，**不是修复前历史版本的重跑**，也不能单独量化全部原生修复的贡献。

实验只连接已启动的独立考场 `25575/25585`，校验考场标记、版本和目录，拒绝生产世界 `25565`，准备及注入前检查在线玩家。每轮使用全新私有记忆；结束时停止调度、撤销身体授权、等待规划与身体收尾、清理考场敌人并确认角色断开。清理未确认会将本轮标记失败并停止后续重复。启动方法见 [技能考场说明](minecraft-skill-exam.md)。

结果写入 `var/minecraft/skill-exam/efficiency/<run>/<trial>/result.json` 和 `events.jsonl`，包括源码指纹、实际模型、服务器证据、控制权并发峰值、清理状态和延迟指标。持有原生技能控制权不等于移动或完成工作，必须结合服务器检查点；模型耗时可能与身体执行重叠，不能直接相加。未观测到的时间指标保留 `null`，不计成零延迟。

本文件记录设计和复现方法，不预填实测成绩。实际运行结果与对照结论以本轮 `var` 报告为准；固定短考题不等于开放世界持续生存能力。
