# Minecraft 四人格末影龙试炼

> 历史战斗诊断。当前主目标已改为 [随机世界空手开始的完整生存](minecraft-survival.md)。本模式的辅助装备、效果、传送及战斗进展不计入完整生存结果。

这次实验让谢耳朵、福尔摩斯、死侍、胡一菲四个 NPC 进入同一个 Minecraft Java 1.21.4 末地世界，自行观察、交谈、选择工具并尝试击败末影龙。目标是验证人格、独立记忆、事件调度与真实游戏行动能否一起工作。

世界中的共同设定是“击败末影龙可以帮助大家逃出这个世界”。每个 NPC 私下知道自己是合成人格，对外声称自己是人类意识上传者，并初始相信其他居民是真正的人类上传者。这是游戏内的虚构角色设定；现实产品性质仍是 AI 角色模拟。

## 分层与技术选择

| 层 | 实现 | 职责 |
| --- | --- | --- |
| 世界 | 本机 Minecraft Java 1.21.4 服务器 | 权威位置、血量、碰撞、物品、伤害、龙阶段和胜利进度 |
| 身体与感知 | Mineflayer 核心 API | 用玩家连接接收世界状态，发送移动、交互、近战和弓箭操作 |
| 世界适配 | `adapters/minecraft/src/world.ts`、`native-actions.ts` | 感知过滤、距离校验、串行行动、取消与执行回执 |
| 调度 | `packages/bridge/src/npc-scheduler.ts` | 合并事件、控制唤醒频率、每人串行、最多四人并发、超时退避 |
| 决策 | `packages/pi-runtime/src/world-agent.ts` | pi-agent-core 工具循环、上下文与预算控制 |
| 人格与记忆 | `packages/npc-core/src/world-persona.ts`、`world-memory.ts` | 文字人格、原作检索、各 NPC 自己的世界经历 |
| 模型 | CLIProxyAPI 兼容接口，经 `loadModel()` 调用 | 生成文字与工具请求 |

本次执行层使用 Mineflayer 原生能力。Pathfinder 和网页 3D Viewer 不参与运行。观察提供结构化数据；人类可用普通 Minecraft 客户端进入同一个服务器看过程。

NPC 对世界依赖的是 `observe()`、`execute()` 和场景公开资料接口。人格、记忆与 pi 编排不依赖 Mineflayer 实例，以便之后替换世界实现。

## 低难度设置

具体规则以 [dragon-scenario.ts](../adapters/minecraft/src/dragon-scenario.ts) 为准。

- 使用独立存档 `var/minecraft/dragon-lab/server/world`，保留原来的创造模式沙盒。
- 游戏模式为生存，难度为 Easy；直接将四位 NPC 送入末地，不包含从零采集、寻找要塞等前置流程。
- 保留死亡物品并立即重生；关闭自然刷怪、PVP、生物破坏、摔落伤害、火焰伤害和溺水伤害。
- 配发保护 IV 下界合金全套、锋利 V 下界合金剑、力量 V／无限弓、箭、金胡萝卜、圆石和镐。
- 提供抗性提升 II、生命恢复 II、缓降和饱和效果。
- 移除水晶外部铁栏杆，降低固定目标射击难度；不直接移除水晶。
- 保留原版末影龙及其血量与阶段逻辑。场景设置拒绝直接 `kill`、`damage`、改写 `Health` 和授予胜利进度的捷径。

这些是明确的实验辅助条件。成功意味着在这些辅助条件下完成游戏目标，不应描述为原版无辅助生存通关。

## 运行

在项目根目录安装依赖并准备 Minecraft 运行环境：

```powershell
cd E:\humanclone\anima
npm ci
npm run minecraft:setup
```

通过本地 `.env` 配置模型接口，参照根目录 `.env.example` 中的 `ANIMA_API`、`ANIMA_PROVIDER`、`ANIMA_MODEL`、`ANIMA_BASE_URL` 和 `ANIMA_API_KEY`。CLIProxyAPI 通常在 `http://127.0.0.1:8317/v1`；模型 ID 应使用代理实际可用的条目。

角色材料放在 `data/roles`。加载时优先选择 `data/roles/<id>/profile.json`；若缺少该文件，则在内存中组装已有 `.claude/skills/<id>/` 下的性格、记忆、元数据与证据索引，并核对数据来源。两种本地档案都标记为 `local-profile`，不需要重复生成文件。如果完全没有本地角色目录索引，会明确使用代码内自拟的简短起步人格；损坏或不完整的已有档案会报错，不会悄悄伪装成完整复现。

启动试炼：

```powershell
npm run minecraft:dragon
```

该命令会在后台启动本机控制 API、独立 Minecraft 服务器和四个 Bot，并在准备后启动自主调度。如果此前运行的是普通沙盒，先运行 `npm run minecraft:stop` 关闭旧服务，再启动试炼。

只准备世界、暂不自动调用模型：

```powershell
$env:ANIMA_MC_AUTORUN = 'false'
npm run minecraft:dragon
```

控制页面默认是 `http://127.0.0.1:18791`，Minecraft 客户端连接 `127.0.0.1:25565`。HTTP 的 `GET /api/experiment` 返回试炼与调度状态，`POST /api/experiment/start`、`POST /api/experiment/stop` 启停调度；接口需要本地会话认证。停止调度不会关闭游戏世界。

关闭控制服务、Bot 与由它管理的服务器：

```powershell
npm run minecraft:stop
```

停止不会删除存档和记忆。再次启动会加载保存的数据；需要全新试验时应另行归档旧存档和 NPC 记忆，不能将续跑当作全新初始条件。

## NPC 的工具与身体能力

pi 层提供 `observe`、`action`、`recall_character`、`remember`。其中 `action` 可以请求以下身体操作：

| 行动 | 当前行为与限制 |
| --- | --- |
| `goto` | 32 格内直线靠近，允许约 1 格误差；没有自动寻路，1.5 秒没有进展就反馈失败 |
| `move` | 指定前后左右、跳跃、疾跑、潜行等控制，单次最多 5 秒 |
| `look` | 看向 32 格内的坐标 |
| `say` | 最多 250 字符的单行聊天，不能发送斜杠指令 |
| `dig` / `place` | 4.5 格内挖掘、放置；需要实际物品，不挖脚下承重块，并检查世界更新 |
| `equip` / `consume` | 从背包装备到主手、副手或护甲位，使用主手食物 |
| `interact` | 与近处实体或可见方块交互 |
| `toss` | 丢出指定背包物品，单次最多 64 个 |
| `attack` | 对当前实体发起原生近战，最长 10 秒，按可接触边界检查 3 格距离 |
| `shoot` | 从背包装备弓、蓄力约 1.1 秒并射向可见实体；考虑空气阻力和重力 |
| `wait` / `stop` | 短暂等待或取消当前控制 |

`attack`、`shoot` 和实体 `interact` 都传 `nearbyEntities[].id`。末影龙在 1.21.4 是多部件实体；执行层把龙根 ID 转成身体部位 `rootId + 3`，使用身体的 5×3 碰撞范围。龙头位置依赖飞行历史，本版不猜测龙头位置。这里描述的是实现依据，真实有效伤害仍需实测确认。

弓箭补偿使用每 tick 初始速度 3、空气阻力乘数 0.99、重力 0.05 的离散轨迹，求可行的较低发射角，计入箭生成点低于眼睛约 0.1 格。它主要适用于静止水晶；原版散布、角色移动、服务器延迟、障碍和移动目标仍会影响命中。无法到达的弹道直接返回失败，例如水平 90 格且高 30 格的目标不应在本模型中被承诺可达。

每个 NPC 只执行一个身体行动，每次行动有 15 秒取消期限。取消会清除移动控制、结束挖掘和持物使用；底层原生 Promise 不接受 AbortSignal 的情况下，保留行动锁直到它结束，防止旧行动与下一轮重叠。已经发出的交互无法回滚，例如取消弓蓄力可能同时释放一箭。

## 感知、调度与独立记忆

实体观察限定为当前加载世界中 96 格内通过遮挡检查的实体，分别检查最近点、中心和接近顶部的位置，任一点能看见即可，避免把露出塔沿的水晶误判为完全不可见。观察包含 ID、类型、位置、距离以及客户端确实收到的血量；不知道的血量返回空值。近处方块只返回 6 格内最多 18 个可见实体方块。背包、装备、自身血量、饥饿和维度也进入观察。

聊天目前在 Bot 侧按 16 格筛选。默认游戏聊天本身仍可能向服务器广播；这个过滤定义了 NPC 的接收范围，不等于服务器已经实现了完整空间语音系统。

调度器按事件与空闲周期唤醒角色，合并重复事件，并对 NPC 互相聊天做冷却。它不把自己刚刚执行的动作当作新唤醒来源。每个决策轮最多 6 个行动、8 轮模型调用、90 秒；动作失败、模型超时与死亡后会按实际结果记录，并在后续轮次重新观察。

每人的记忆文件是 `data/world-memory/dragon-<runId>/<npcId>/<roleId>.jsonl`，NPC 工具只能访问自己的实例；早期原型使用过 `minecraft` 命名空间，当前不自动导入这些旧经历：

- `fact`：亲眼观察、生命事件和实际执行回执；记录失败也属于事实，不表示目标成功。
- `hearsay`：某个角色说过的话，不自动当成真实世界状态。
- `intent`：计划、假设和提醒，由 `remember` 保存。

原作片段和关系作为人物背景，不能自动变成当前 Minecraft 中已发生的关系。世界旧记忆通过轻量关键词检索加近期记录装入上下文，目前没有依赖向量数据库。

这里的“独立”指 NPC 之间不共享或越权读取彼此记忆；运行机器的操作者可以查看本地日志。原始角色材料、衍生档案、游戏经历、私聊和运行凭据均保存在 Git 忽略的 `data/`、`var/` 或 `.env`，不作为开源示例提交。模型上下文仍会发送给配置的代理和其上游模型服务，并非全部离线计算。

## 结果与验证口径

**端到端战斗结果：待实测。** 不能凭 NPC 的文字声明或工具返回 `completed` 判断已击败末影龙。

验证分为三个层次：

1. **操作**：`shot` 或 `attempts` 仅表示发射／攻击操作已发出；`completed` 只表示该行动流程结束。
2. **世界变化**：读取服务器的龙血量、剩余水晶、龙阶段与存在状态。多人同时攻击时，血量变化不直接归因于某一个 NPC。
3. **胜利**：试炼曾观察到活龙；随后服务器中不存在龙；且至少一位参与者获得服务器自然颁发的 `minecraft:end/kill_dragon` 进度。三项满足才将状态标为 `victory` 并停止调度。

便于审查的本地文件：

| 路径 | 内容 |
| --- | --- |
| `var/minecraft/dragon-lab/run.json` | 当前试炼状态、规则、角色行动/攻击/死亡计数与胜利检查 |
| `var/minecraft/dragon-lab/admin.jsonl` | 场景管理命令，用于核对辅助条件 |
| `var/minecraft/events/<npcId>.jsonl` | 各角色感知、行动与任务事件 |
| `var/minecraft/server-console.log` | Minecraft 服务器日志及只读计分查询结果 |
| `var/minecraft/api-console.log` | 控制服务与调度错误 |
| `data/world-memory/dragon-<runId>/` | 此诊断场景各 NPC 独立的持久记忆 |

可运行 `npm run test:world` 检查 Agent、调度器、原生执行层与场景判定。原生执行层测试包括取消后不遗留移动、取消装备后不继续放置、近战距离、龙部位映射、生命事件、远处水晶观察和弓箭弹道数值检验。数值测试验证的是物理近似计算，不能替代真实服务器上的命中和胜利证据。
