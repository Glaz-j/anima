检查日期：2026-10-01。结论：适合 Anima 的中文影视角色建模实验。多个具名角色有数百段对话和上千条本人台词，可以同时研究文字人格档案、情境检索和关系相关的回应方式。

来源：[scutcyr/CPED](https://github.com/scutcyr/CPED)，固定提交 `1e4b81c28a123f22387e06664f37e5dc9322380f`。三份原始 CSV、README 和 LICENSE 已下载到 `data/public/cped/raw/`，并核对 Git blob 与 SHA-256；这些数据被 Git 忽略。本轮没有生成完整人格、调用模型 API 或读取私人聊天。

## 为什么值得用

原始数据同时提供 `TV_ID`、`Dialogue_ID`、`Utterance_ID`、`Speaker`、`Utterance`，可以可靠关联同一来源角色的多段对话，并保留对方说了什么。

`Scene`、`Emotion`、`Sentiment` 和 `DA` 提供额外的检索或评测维度，例如相似处境中的反驳、安慰、讽刺和道歉。未来可以将这些参考标注用于检索历史材料，但不能把待预测回复的真实情绪标签提前输入模型来宣称预测成功。

五个大五人格维度是 `high / low / unknown`。作者说明，标注者观看材料后为角色填写 BFI-2，再合成这些分类。它们是对虚构角色的解释，不是演员本人的测量结果，也不是不可质疑的标准答案。[标注方法](https://arxiv.org/html/2205.14727v1#S3.SS2)

## 适配与评测边界

1. **人物身份按 TV_ID 加姓名区分。** 当前数据中“方圆”“童文洁”等名字出现在不同 TV_ID；不能因为名字相同就合并。跨季角色也需要明确映射和所处阶段，第一轮先不合并。
2. **“其他”保留为上下文，不建立人格。** 这是多个配角的统称，转换后 `sender_id = null` 并记录 `speaker_is_grouped`。由发言标签数得到的参与人数只是下限。
3. **多人对话保留每位说话人。** 全库有 120 段三个说话人标签、2 段四个说话人标签的对话，不能把所有非目标角色都丢失身份地折成“对方”。
4. **不补造剧情时间。** CSV 没有真实时间戳、集数和剧情日期，也没有明确的受话人标注。`timestamp` 等字段留空，`Utterance_ID` 的末段只用于会话内排序。不能把数据编号当作人物成长时间线。
5. **标注需要复核。** 例如少数角色的年龄、性别有已知标签与 `unknown` 混用。原文和标签均原样保留；人物稳定特征、即时情绪与事实记忆需要分开提炼。
6. **现有 train / valid / test 按剧集划分。** 吕子乔这份材料全在上游 test；用它探索不代表进行了上游基准评测。要测试同一角色的重建能力，需要另按完整会话留出测试材料，同时保存原始分区信息。
7. **控制模型对作品的先验知识。** 初次评测建议隐藏角色名和作品名，并比较无档案、仅文字档案、档案加检索三种情况。隐藏名字只能降低先验影响，无法保证模型没见过这些台词。

当前角色包沿用已有消息记录的 23 个顶层字段。人物参考标签放在旁路文件，不随台词自动注入。未来接入 yourself-skill 时可以逐会话生成角色输入，再沿用文字档案分析流程，无需改动原始 CSV。

## 我们的第一轮实验

建议先选吕子乔（TV_ID 27），对 197 段会话按完整会话做材料划分。模型只依据建模部分的台词归纳有证据的性格、表达习惯和情境反应，原始大五标签先留作参考。

接着用留出场景及新场景比较：纯基础模型、文字人格档案、文字档案加历史情境检索。检索记录保留对方身份、上文、本人回应和来源 ID，以判断表现来自我们的档案和检索，还是仅来自模型本来就熟悉该角色。

苏明玉可以作为第二个案例，检查方法能否处理另一种关系和情境组合。此阶段不需要先训练模型，也不需要安装上游整套深度学习环境。

## 重现

Python 3.10+，仅标准库。在 Anima 根目录运行：

```powershell
python -B -X utf8 scripts/datasets/inspect_cped.py
```

脚本下载并核对固定版本，生成全库角色目录和默认两份包。已有输出不覆盖。要选择别的角色或重跑到新目录：

```powershell
python -B -X utf8 scripts/datasets/inspect_cped.py --character "7:罗槟" --output data/public/cped/inspection-luobin
```

身份边界测试：

```powershell
python -B -X utf8 -m unittest discover -s scripts/datasets -p 'test_cped.py' -v
```

### 对我们当前路线的建议

第一批可以用吕子乔（已有 CPED 角色包）、Sheldon（RoleBench 剧本材料）、Chandler（MELD）作为三个起点，分别测试中文表达、规则与习惯、幽默与社交回应。若希望先看角色扮演效果，可以加入 ChatHaruhi 的白展堂或 Snape，并把现成设定标成外部人工材料；它与“完全由台词归纳档案”的实验应分别记录。

沿用现有 NPC harness：材料适配器负责保留角色、场景、顺序和来源，文字档案生成与检索在 NPC 层处理。原作知识、人物关系与世界统一身份设定分开保存。无需因为换角色数据库而先改 world 或引入微调。

这批选择用于公开材料实验；上游代码许可证、数据发布条件和影视角色本身的使用范围应分别记录。特别是 HPD 官方明确以非商业研究为目的，并说明通过位置索引和抽取工具获得小说对话；本轮不把它描述为无条件再分发的完整小说台词包。ChatHaruhi 官方也明确区分 Apache-2.0 代码与角色权利。项目继续共享处理代码、统计和上游链接，下载材料保留在本地忽略目录。
