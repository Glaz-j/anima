# 双循环身体控制核心

`packages/bridge/src/body-controller.ts` 提供与 Minecraft 无关的 `BodyController<State, Goal, Action>`。它是一个单身体所有者控制器；规划模型、人格记忆、实际技能和世界裁判位于其外侧。

## 接入端口

- `readState()`：同步读取这个 NPC 已知的最新状态。
- `select(state, intent, current)`：同步返回 `run`、`wait` 或 `complete`。每次 tick 都可以检查紧急状态，不等待模型或技能结束。
- `canStart(state, skill, intent)`：可选的同步前置条件验证。恢复和抢占完成后会重新选行为，再验证，旧候选动作不会进入延迟队列。
- `execute(action, signal, reportProgress)`：启动异步技能并返回其**全部操作实际停止之后**才 settle 的 Promise。技能内部负责其移动、攻击等控制节奏，并合作响应 AbortSignal。技能 Promise 不能在遗留移动/挖掘子任务尚未收尾时提前返回。
- `halt(reason)`：立即停止当前控制输入，可返回异步收尾 Promise。执行与 halt 两个 Promise 都收尾后才能释放身体。
- `onEvent(event)`：发送短事件给规划层、裁判和诊断。不要在观察回调中启动未纳入控制器的身体操作。

`readState/select/canStart` 不应执行 IO、模型请求、完整寻路或昂贵搜索。Node 的定时器没有硬实时保证；CPU 密集规划需要限时切片或外置执行。`tick()` 只发起技能，并立即返回。`start()` 默认启动 50ms 的本地检查；控制检查次数与有效 APM 必须分别计量。

## 规划层的授权

规划层提交 `BodyIntent`：

```ts
{
  id: 'gather-wood-01',
  version: 1,
  expiresAt: Date.now() + 120_000,
  goal: { /* 世界适配器定义的目标和约束 */ },
  allowedReactions: ['surface', 'eat', 'defend', 'flee'],
}
```

- `submit(intent)` 接收比已见版本严格更新、期限有效的意图。立即撤销旧技能授权，但不绕过其收尾。
- `renew(expectedVersion, expiresAt)` 只延长仍有效的当前授权，保留版本、执行、进度与移动边界；过期或已撤销的授权不能续租。
- `cancel(version)` 是一个有新版本号的取消命令。它清除目标；旧版本的取消或迟到规划结果被拒绝。
- `stop()` 每次调用都递增版本、锁存停止，撤销授权并返回收尾 Promise；不因技能结束、计时器 tick 或 `submit` 自动恢复。先前观察对应的、已在途的恢复命令也失效。若技能永不收尾，该 Promise 也不会假装完成。
- `resume(newIntent)` 以新的有效版本显式解除停止。旧意图不能恢复。
- 意图到期、或 selector 用 `complete` 结束全部授权时，也会递增控制版本。基于结束前观察生成的迟到计划不能重新启动工作。`submit/resume/renew` 在处理命令前检查到期，即使下一次控制 tick 尚未来临，过期版本也不能抢先续命。
- `dispose()` 停止定时器并永久关闭控制器，等待执行收尾。
- `snapshot()` 返回隔离副本，包括当前意图、身体技能/收尾阶段、有限的回执记录、累计指标。

规划模型自己的请求超时或一轮思考结束，没有连接到身体 AbortSignal。仍在期限内、仍有效的目标继续执行。显式取消、替换、停止和意图过期撤销旧授权；技能超时会取消该次技能并退避，不会把整个授权假装完成。

## Minecraft 的工作目标与自保策略

工作目标完成和身体授权结束是两个事件。Minecraft 适配器确认全部步骤完成后，只发一次 `goal-finished`，将 `goalStatus` 标为 `completed`、`workCompleted` 标为 `true`。如果意图仍有授权的应急反应，就继续观察和自保，直到原期限到期或大脑明确撤销；没有应急授权时才清除意图。空步骤表示 `watching`，不是完成了一项工作。`cancel`、`stop`、expiry 都撤销目标和全部反应授权，不会自行恢复或续期。

提交与当前步骤、策略、应急授权等价的计划时，适配器只续租，不重新执行已经完成的步骤，也不打断当前技能。需要从头重做时，规划层必须显式提交 `restart: true`。

移动边界按实际工作阶段确定。显式 `combat/retreat` 步骤在第一次真正启动时记录位置，等待前一技能收尾期间不提前固定；同一步的时间片、重试、打断后恢复和等价续租共享该位置。半径仍取步骤 `maxDistance` 与大脑 `policy.chaseRange` 的较小值。新计划可以明确选择新的步骤，但不会因此重置正在持续的自保遭遇。

`defend/flee` 共用一次连续威胁遭遇的起点。换敌人、换反应、换时间片、续租、替换计划以及单纯停止后恢复，都不能逐步向外移动这个起点。只有已经没有反应运行或收尾，并连续观察到 2 秒安全，才允许下一次遭遇采用新位置。安全判断使用比威胁进入半径宽 2 格的退出边界；近处仍有敌人、受伤、水中或熔岩危险会打断这个安全窗口。死亡、重生和维度切换会清除旧身体/世界的锚点，但不会自行恢复已停止的授权。

这项边界修正避免了另一种执行空洞：若整个意图只共用提交位置，合法计划先旅行到远处后，自保也会被错误判为超出旧范围。现在边界从对应步骤或遭遇开始，同时仍阻止连续追击通过时间片或反复规划无限延伸。

这两项调整来自实际运行中的空档和重启问题：原先把工作完成等同于授权结束，NPC 会在等待下一次思考时失去已授权的自保；原先每次重复规划都替换意图，会反复打断技能、清空进度。现在工作完成单独回报，持续策略保留自己的期限，重复规划续租即可。

目标完成但仍保留应急授权时，版本和期限保持不变；整个授权完成或到期时才失效该观察版本。终止事件中的 `intentVersion` 标识被结束的旧意图，新的可提交版本应从 `snapshot().version` 读取。

当前 Minecraft 的快速选择由本地规则实现，支持 `surface/eat/defend/flee` 四种授权反应；尚未接入快速决策模型，也没有通用 `unstuck` 应急授权。已有持续技能不代表这些技能在所有地形、敌人和组合任务中都可靠，能力以独立考场的真实服务器证据为准。

## 宿主恢复边界

NPC 的具体工作计划与宿主默认生存授权分开。明确开始自主运行、或通过校验的新手动任务，可以在模型请求前授予一次 `steps: []`、120 秒、`surface/eat/defend/flee` 的生存 lease；已有有效工作计划保持原样。它不复制死亡或停止前的步骤，也不代表任何工作已经完成。首次版本 0 的普通任务仍保留同样的初始空步骤行为。serial/parallel 对照的默认授权不含任何自动反应。

自主会话由宿主 start/stop 管理。只有参加仍有效自主会话的 NPC，在真实 death/respawn 后收到 spawn，才可在原身体动作确实收尾后消费一次恢复票据。新手动任务本身不创建持续的重生授权。每 NPC 的宿主代次与身体版本共同校验票据；人工停止、全局停止、断连、内部 halt 失败及后来的控制版本变化，都能让旧回调失效。CAS 失败不追逐新版本重试。全局调度器仍在运行或重复点击已运行的 start，不会解除单个 NPC 的人工停止。

手动请求在异步读取正文前捕获票据，随后先验证任务文本、ready、任务占用及身体收尾状态，最后才解除停止锁。身体内部 halt 故障还要求检查后显式提交有效的控制恢复，不能靠重生或新任务自动解除。普通模型唤醒、模型超时、`cancel_body`、工作完成和 lease 到期，都不会产生新的宿主授权；具体计划的续租仍是规划层的职责。

这解决的是恢复时的授权空窗：原先 death/respawn 已停止身体，但调度器只是重新叫醒大脑，身体必须等模型返回 `resume` 才能自保。现在仅在明确的新运行边界先赋予有限生存能力，旧工作和旧模型回调都不能随之复活；没有新增常驻恢复循环。

## 快速行为选择

`run` 包含 `key/action/priority`，以及可选 `reaction/timeoutMs/minRunMs`：

- `key` 标识完整技能实例的含义，必须包含会改变执行对象的参数，如目标实体或采集资源，不能所有动作都叫 `move`。
- 同 key 表示继续当前技能，控制器不会每次 tick 重启。当前技能是否仍安全由 selector 在每次观察中判断。
- reaction 必须包含在大脑明确授权的 `allowedReactions` 中。选择了未获授权的反应会撤销当前工作并报告阻塞。
- 更高优先级可立即请求抢占；同优先级或更低优先级的切换，默认要求候选持续 150ms、旧技能至少已运行 250ms，降低边界抖动。世界策略还应使用合适的进入/退出阈值。
- 无法启动高优先级紧急行为时，会先停止较低优先级工作并报告阻塞，不能继续危险的采集或向前行走。
- `wait` 表示没有可执行的授权动作，并取消当前技能；不是“忽略本次检查，继续当前技能”。需要继续就返回同 key。
- `complete` 表示 selector 已从真实观察确认目标完成。控制器发出 `intent-finished` 并清除目标；这个判断不能仅依赖工具说“成功”。

Minecraft 的工作步骤完成但仍需保留应急策略时，selector 发出独立的 `goal-finished`，平时返回 `wait`，遇到授权的危险则返回对应 `run`，不返回清除整个意图的 `complete`。

`select` 和 `canStart` 返回后都重验期限。即使某次同步计算耗尽了剩余授权时间，或返回的仍是当前同 key 技能，也必须停止旧授权。

取消后不缓存新的动作，旧操作完全收尾后再从最新状态选择、验证技能。低优先级目标仍保留；临时应急结束后可重新推进剩余目标。

## 收尾与失败

身体只有 `running` 或 `draining` 两种占用状态。技能取消后超时只发出 `intent-blocked`，**永远不依靠超时假释放控制权**。如果 halt 本身失败，控制器锁存停止，要求外层显式恢复。

每个结束技能都会记录 `BodyReceipt`。被撤销的技能主状态是 cancelled；其 `result` 仍保留真实晚到的结果，例如在取消过程中实际又拾取了一块木头。外层应据真实结果结算资源，但不能让旧回执覆盖新的意图。

普通失败、执行器自行取消、技能超时后使用按 key 的有界指数退避，默认 1 秒起、最大 30 秒。大脑有意替换/取消、紧急行为抢占不会阻碍旧目标恢复。遥测回调异常不释放身体，也不打断控制循环。

## 已有验证及边界

`node --test tests/body-controller.test.ts` 覆盖连续 tick 不等待、单所有者、紧急抢占、异步 halt 收尾竞态、超时不假释放、前置条件重验、stop 锁存、版本/期限失效、失败退避、防抖和真实定时器运行。

`node --test tests/minecraft-body.test.ts tests/input-telemetry.test.ts` 覆盖适配器的目标完成与策略续存、重复计划续租、显式重做、步骤/连续遭遇的固定追击边界、先旅行后反应、威胁退出与生命周期重置、真实输入口径，以及 Mineflayer 延迟注入控制 API 后的遥测安装。

`tests/dual-loop-baseline.test.ts` 经真实 World、LLM 接口和原生动作路径，使用模拟模型响应验证三种实验模式：serial 等同一身体目标实际结束或首次技能失败，parallel 立即返回，两者都禁用应急反应；dual 保留明确授权的反应。serial 技能失败后撤销剩余步骤并交回真实失败，让规划有机会纠正，而不是等待错误动作重试到租期结束；正常战斗时间片结束仍不等于击杀。延迟施加于每次逻辑模型请求，包括工具回执后的第二次请求。serial 脑轮取消只撤销自己等待的版本，不取消或等候外部新版本；parallel/dual 的模型等待与取消不接管身体。这些验证没有模拟真实 Minecraft 物理或模型规划能力。

这些是控制核心的生命周期和并发验证，不能代替 Minecraft 战斗、跑酷、合成等真实题目的技能能力测试。接入适配器必须自行提供动作执行、完成条件、健康/威胁策略和世界事实裁判。

## 大脑需要可用于纠正计划的回执

每次执行模型请求开始前重新读取一次本 NPC 的身体状态，注入有界权威摘要。当前版本、停止状态、期限、下一步和挂起原因覆盖旧观察；读取失败使该请求无法提交身体计划。模型生成期间世界仍可能变化，因此回复到达后仍执行原有版本校验，不能自动换成新版本、续租或解除人工停止。

Minecraft 的明确导航／单跳拒绝会挂起当前工作步骤，`control.replanRequired` 保留原始版本、步骤、回执 ID、停止码与原因；`goalStatus=blocked` 不等于整个身体停止。已有进度和部分资源变化照常记账，授权内的浮水、进食和自保仍优先工作。相同计划续期保持挂起；大脑重新观察后提交新计划或显式 `restart` 才允许再次尝试。取消、正常时间片结束及尚未分类的短暂错误不进入该路径。外层导航的最终停止原因优先于其保存的历史障碍，避免把“绕行后尚未落地”误认成永久障碍。这表示本次执行器需要重评，不证明游戏世界绝对不可达。

单跳采用原生 `PlayerState` 模拟候选输入并检查沿途身体空间、危险、起跳支撑及稳定着陆；不再用额外的理想抛物线拒绝真实物理允许的低顶台阶。静态场景回归覆盖碰顶登上一格台阶，以及实墙、火和未加载空间的拒绝；它不代表动态障碍下的所有跳跃都可靠。

身体独立运行后，旧的“工具调用结束，模型立即看到完整结果”不再成立。`body_status` 和观察摘要必须保留当前未完成步骤、具体失败原因，以及实际到达、落地、击杀、库存确认和材料消耗等必要结果。仅返回 `failed` 会让规划层知道出错，却不知道应当改目标、改工具还是等待。

真实材料跑酷曾暴露这一问题：身体完成水平搭桥后，规划层反复尝试超过短跳能力的高差；原压缩回执丢掉了执行器的 `result.error`。现在有界回执保留错误与 `stoppedReason`，并保留长计划中下一未完成步骤的原始索引，重复压缩也不丢失。技能边界在工具说明中公开，不加入考场路线或标准答案。是否改善规划，仍须完整 Agent 实测验证。

## 实服控制权检查

在独立考场空闲时运行 `node adapters/minecraft/benchmark/ownership-probe.ts --run`。可信夹具先恢复平地，然后用真实行走、服务器位置和输入状态验证人工停止、旧版本拒绝、显式恢复、等价续租、替换时单一所有者、TTL 到期停止。结果写入 `var/minecraft/skill-exam/ownership/`；它是控制权正确性证据，不作为技能成绩。未带 `--run` 时只显示说明，不连接服务器。
