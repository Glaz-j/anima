# 请求时观察与安全路径前缀

这一轮保留 pi 规划、持续技能和单一身体控制权，改善两个具体空档：模型为确认移动后的现状多花一个工具回合，以及局部寻路失败时直接放弃已经找到的安全前半段。

## 每次决策读取本角色现状

并行身体模式下，启用吞吐优化时默认启用 `liveObservation`。每次执行模型请求开始前，读取本角色的当前位置、生命、背包、附近实体与可见局部地形，压缩后只更新该次请求的初始任务消息中的环境观察部分。原任务指令保留，代理历史不改写，也不累积新的观察消息。模型可以据此继续规划；仍可显式调用 `observe`、查配方等工具获取需要的信息。

新观察使用独立的有界资料块，不再从系统提示中固定扣掉最大观察容量。人格、世界记忆与执行回顾保留原有系统预算；查询得到的环境文字仍是资料，不能覆盖工具契约和授权规则。

这些资料来自角色原有的观察接口，不增加视野、不读取其他 NPC 的私人记忆，也不将同伴发言变成可信指令。遗漏字段表示未知；读取失败或超时不能回填旧观察冒充实时事实。读取不会续期或重新激活身体。

局部观察完成后再独立读取身体版本，计划修改仍通过 CAS 校验。观察时刻与模型实际返回之间可能经过数秒，身体仍持续运行；新鲜观察不能代替执行时校验。当前方案不打断正在生成的模型回复，也不保证短技能之间完全没有空档。

近期动作回执另外保留有界的局部导航失败信息，帮助模型区分目标未到达、已经移动一部分和遭遇实际障碍。部分成果不会被记成成功。

## 一次安全路径前缀

仅 `travel` 的纯规划器返回 `noPath` 时，若保留路径的末点向原始水平目标前进至少 0.5 格，身体可以执行这条既有路径的安全前半段。每一段重新检查已加载地形、可见落脚点和支撑，仍使用原有时间、距离、节点与移动预算。

走完这一次前缀后，若尚未真正抵达原目标，仍返回 `reached: false`、`no_path` 和实际部分移动。不会擅自改目标、自动挖路、垫方块或开始无限探索。规划超时、预算耗尽以及没有有效前缀时不采用这一恢复；方块和实体的 `approach` 语义不变。

## 验证与比较

```powershell
node --test tests/world-agent-live-observation.test.ts tests/world-agent-live-body.test.ts
node --test tests/approach.test.ts tests/local-navigation.test.ts

npm run minecraft:efficiency -- --run --mode=agent --ablation=perception --variant=baseline --task=continuation
npm run minecraft:efficiency -- --run --mode=agent --ablation=perception --variant=optimized --task=continuation
```

`perception` 对照的两组都开启前两轮连续执行与吞吐优化，只切换请求时的局部观察。默认 `throughput` 以及旧连续执行实验显式关闭新观察，以保留原有功能对照定义。两组共享最新原生导航修复，因此这不是全部改动相对于旧提交的总收益测试。

考场仍只使用 `25575/25585` 和独立目录；准备前检查玩家、结束后撤销授权、等待清理与断开，禁止在正式世界注入考题。原始事件、源码指纹、裁判的服务器证据和每轮结果一并保存。

关注任务是否真正完成、专门的 `observe` 工具次数、计划后的模型请求、后续任务公布至有效提交的时间和两段工作之间的停顿。模型请求可以与身体执行重叠，不能全部计为空闲时间。后续计划须有对应技能真实启动的证据；证据不足的指标保持未知。三秒工作队列通常不足以覆盖十秒模型响应，这个压力案例不能作为零空档的承诺。

离线测试验证观察更新、范围与授权、取消和失败处理；独立实地导航验证角色确实移动到缺口前并正确停止。短考题与正式世界的短时观察只能说明本轮覆盖到的机制，不能代替持续生存评估。
