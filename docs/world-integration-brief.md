# 世界层接入工作说明

状态：Minecraft、四 NPC 的 pi 工具循环、人格检索与独立记忆已接通；正在验证完整生存流程，尚未完成屠龙。

更新日期：2026-10-02。本文替代此前优先 AI Town 的讨论稿。

## 项目背景

我们正在做 **栖灵 · Anima**：让具有不同人格和独立记忆的 AI 角色，在虚拟世界里自主行动、交流，并逐渐形成各自的经历和关系。

世界层已经确定使用 **Minecraft Java 版**。后续 NPC 的移动、交谈和其他互动在 Minecraft 中验证，原生客户端展示世界，本地 HTTP 控制台用于操作和诊断。独立文字会客室保留作调试和人格对照。

目前已有本地 Minecraft Java 1.21.4 服务器、HMCL 客户端、Mineflayer Bot，以及使用 pi-agent-core 调用世界工具的运行链路。四个角色分别加载人格档案、原作检索和当前世界的私有记忆，由调度器并发运行。正式的跨世界共享协议与持久交付队列尚需完善；公开演示继续使用公开材料，不包含私人聊天及其衍生档案。

## 当前运行范围

- 四人进入随机生成的普通主世界，从空背包开始；角色为谢耳朵、福尔摩斯、死侍、胡一菲。
- 目标是先解决食物、工具、庇护和资源准备，再探索下界与末地，最终击败末影龙。分工、路线和行动顺序由角色根据实际处境协商决定。
- 世界采用 Easy 难度，昼夜、天气、怪物、饥饿、伤害与死亡掉落正常运行。没有预发装备、传送或要塞位置提示。
- 本地 CLIProxyAPI 已接通 pi 的实际工具调用。控制台位于 `http://127.0.0.1:18791`，普通客户端连接 `127.0.0.1:25565`。运行状态以控制台或 `npm run minecraft:status` 为准。
- 旧的直接进入末地场景仅保留作战斗工具诊断；它的辅助装备和战果不计入本次完整生存目标。

## 分工与职责

| 部分 | 负责人 | 职责 |
| --- | --- | --- |
| NPC 层 | 我们 | 人格、提示词、模型调用、长期记忆、关系认知、目标和行动决策 |
| 适配与桥接层 | 我们 | 将具体世界的数据转换为统一协议，交付观察、传递行动、接收结果 |
| 世界层 | Minecraft 与世界侧适配实现 | 地图、角色实体、移动和交谈的执行、世界时间、规则、事件与画面展示 |

世界负责保存“实际发生了什么”，NPC 负责保存“自己知道什么、如何理解”。原始人格材料、私有身份和长期记忆都留在 NPC 层。

当前世界适配位于 `adapters/minecraft/`，存档与运行资源在 Git 忽略的 `var/minecraft/`。人格与记忆在 `npc-core`，Agent 编排在 `pi-runtime`，调度在 `bridge`；Minecraft 的 `llm.ts` 负责连接这些能力与具体身体的任务生命周期。适配器保留观察、动作执行和回执，NPC 不直接依赖 Mineflayer 对象。AI Town 保留为历史候选。

## 第一阶段工作目标

### 1. 把现有世界运行起来

复用已运行验证的 Minecraft 本地服务器、普通客户端与 Bot API。用 `npm run minecraft:survival` 启动或续跑同一生存存档，四个公开材料角色同步运行。启动方式见 [Minecraft 接入说明](../adapters/minecraft/README.md)。

### 2. 让角色可以接受外部控制

世界控制已接到 NPC 思考流程；同一角色一次只执行一个任务，身体动作串行。继续验证受伤、死亡、取消、超时与新任务之间的关系。

已支持移动、交谈、挖掘、放置、合成、有限采集、熔炉和容器操作等原生能力。说话必须真实执行 `say`（近处交谈）或主动选择 `broadcast`（世界频道）；模型最终文字只出现在操作者控制台，不代表其他居民听见。频道只传原话，角色私有记忆不共享。工具报告实际结果，不能把请求成功发送当作材料、装备或伤害已经产生。

### 3. 为适配层提供明确的世界接口

适配层需要能够获取角色位置、附近人物、可感知事件，提交行动，并获取执行结果。

世界侧负责提供原生调用入口或事件出口，我们负责转换为 Anima 协议。接口可以先用普通函数或现有后端接口实现，具体传输方式一起确定，第一阶段不要求单独部署桥接服务。

### 4. 提供独立于 NPC 服务的联调方式

保留 API、组件测试和诊断场景，便于单独检查移动、合成、交谈等能力。生存实验中的策略由 NPC 决定；诊断脚本不代替它们收集资源或完成任务。

## 接入边界

- **行动意图和执行结果分开。** NPC 提出“走过去”或“说一句话”，由世界检查条件、执行并返回结果；失败或被拒绝也要有反馈。收到行动请求不等于行动已经完成。
- **观察按角色分别提供。** 某个角色只能收到它能够看见、听见或获知的信息。调试界面可以展示全局状态，但不能把全局信息直接传给每个 NPC。
- **模型思考不阻塞世界运行。** NPC 等待模型回复时，世界仍可以继续运行；过时或已经无法执行的行动要能明确处理。
- **接口方便将来换世界。** 共同确认角色、地点、事件和行动的标识方式，避免把 Mineflayer 内部对象直接变成 NPC 的依赖。同一人格在不同世界中使用独立实例与经历。
- **世界规则由世界判断。** 适配层负责转换和交付，NPC 负责提出行动，行动是否合法、是否成功及产生哪些实际事件由世界负责。

共享协议已确定观察、行动提案、执行结果、世界能力和公开资料等类别，具体字段尚未冻结。世界侧先提供能力和限制清单，双方再确定第一版接口。

## 第一阶段场景

角色初始身份统一：

> 每个 NPC 知道自己是合成人格，对外声称自己是人类意识上传者，同时起初相信其他居民都是真正的人类上传者。

身份和认知由 NPC 层实现，Minecraft 任务提示已接入统一设定，并加入共同信念：“击败末影龙可以帮助大家逃出这个世界。”原作参考材料与 Minecraft 新经历保留不同来源。第一阶段围绕普通生存、协作、相遇和交流展开，暂不设计额外经济、资源争夺、政治或复杂社会规则。

食物与工具准备、进入下界、找到并进入末地、击败龙，构成整段旅程。控制台只记录已经发生的里程碑，不通过阶段切换给角色发物资、揭示位置或安排固定策略。“九死一生”的过程来自真实世界中的风险、失败与合作，不预设死亡次数或必胜结果。

## 预期交付物

1. 一套可以按文档启动的世界。
2. 外部控制角色所需的世界接口及调用示例。
3. 一份接口说明：支持哪些行动、提供哪些观察、有哪些执行限制。
4. 四角色自主运行、按世界隔离的记忆与可核对的行动日志；另保留无需模型的组件验证。

## 验收场景

局部验收包括角色真实移动、交谈、工具制作与资源获取；不在感知范围内的角色不应直接获知谈话或其他角色的私有记忆。

同一角色不会被多个任务争用。无法执行的行动返回明确结果，模型等待期间世界继续运行。继续验证有限回应、长期协作、死亡后的状态更新与重启后的记忆恢复。

完整验收必须从四人空手出生开始，在同一自然生存存档中完成准备、探索并亲自击败末影龙；胜利由服务器事实确认。当前只验证到初期资源和工具，尚未进入下界或末地。具体记录见 [四人格完整生存实验](minecraft-survival.md)。

## 推进顺序

保持当前同进程 NPC／世界接口，先修复真实运行暴露出的动作执行和感知问题，再观察人物能否维持资源积累与协作。跨世界协议和持久交付机制随后完善，当前无需增加独立服务或消息队列。
