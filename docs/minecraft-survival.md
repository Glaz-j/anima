# 四人格完整生存实验

目标是观察四个有不同人格、私有记忆的 NPC，如何从随机生成的 Minecraft 主世界空手开始，协作获得资源、准备生存、进入下界和末地，最终击败末影龙。人格共同持有“击败末影龙可以帮助大家逃出这个世界”的信念。

这不是直接进入末地的战斗测试。旧的 `minecraft:dragon` 场景保留作身体工具的诊断环境，其装备、辅助效果与战斗结果不计入完整生存实验。

## 启动与观察

在 Anima 根目录安装依赖、准备 Minecraft 和配置模型后运行：

```powershell
npm run minecraft:stop
npm run minecraft:survival
```

打开 <http://127.0.0.1:18791> 查看状态、对话和实际行动。原生客户端连接 `127.0.0.1:25565` 可以进入同一世界。四位角色沿用本地公开角色材料：谢耳朵、福尔摩斯、死侍、胡一菲。客户端中的人的行动也会改变实验世界，观察时应避免替 NPC 收集或提供资源。

`npm run minecraft:status` 提供只读终端报告，包括实际背包、进度、调度状态和近期事件，不打印本机会话密钥。

默认准备完毕后启动四个模型循环；`ANIMA_MC_AUTORUN=false` 只连接角色，需在控制台点击开始。停止自主调度会取消任务，但 Minecraft 世界继续运行；需要同时停止昼夜与怪物的模拟时，用 `npm run minecraft:stop` 保存并关闭服务器。再次启动会续用同一存档和记忆。

## 世界规则

- 随机种子，普通地形和自然结构，Easy 难度，生存模式。
- 四人自然出生，首次行动前核验全背包及装备槽为空。
- 昼夜、天气、怪物、饥饿、自然回血、受伤和死亡掉落正常生效。
- 不发装备或增益，不传送角色，不透露要塞位置，不修改龙血量，不代替 NPC 完成进度。
- 小范围出生半径便于初始相遇；后续移动、探索、集合和交流由角色完成。

服务器只设置普通生存规则，并只读检查自然进度与末地战斗状态。NPC 工具没有服务器控制台指令入口。

## 自主决策与身体操作

NPC 层加载文字人格、按需检索原作材料，并将当前世界的亲历事实、听说与个人计划分开保存。调度器最多并发运行四人，每人的身体动作串行执行。世界适配器只提供可执行动作和实际回执。

在原有观察、说话、移动、挖掘、放置、装备、进食、交互、近战与射箭之外，增加有限的生存动作：

| 操作 | 作用 |
| --- | --- |
| `scan` | 查找已加载且可见的资源或实体；标记候选预算与返回截断，空结果不代表资源不存在 |
| `broadcast` | 主动使用 Minecraft 世界频道发送短句，可跨距离与维度商量；接收方只获得原话 |
| `recipes` | 查物品配方与工作台要求 |
| `craft` | 使用实际材料合成物品 |
| `gather` | 组合有限移动、挖掘和拾取，报告实际背包变化 |
| `approach` | 接近当前可见方块或实体，身体选择交互站位；只移动，后续交互由 NPC 决定 |
| `travel` | 走向 NPC 自选的水平 X/Z 区域，身体寻找合法高度和路线，用于探索或返回地点 |
| `smelt` | 操作附近熔炉，放入实际原料与燃料、取出已有产物 |
| `container` | 查看、存入或取出附近容器内的物品 |
| `sleep` | 使用可到达的床，服从游戏本身的睡眠条件 |
| `use_item` | 用主手或副手使用物品，可瞄准或短时按住；回执不把发送操作当作效果已发生 |
| `fish` | 使用真实鱼竿向自选的可见水方块尝试一竿，等待自身鱼钩咬钩并收线，报告实际背包变化 |
| `attack` 的 `follow=true` | 在 NPC 选定的总时限内追近并攻击同一可见实体；缺省仍为原地挥击，不自动换目标或装备 |
| `posture` | 显式启用限时浮水姿态，空闲和思考时在实际接触水体处按跳跃；其他身体动作优先，`none` 关闭 |

观察包含角色近处可见的落脚点、放置空格和危险地形，候选点不保证路径畅通。可见掉落物通过服务器实体元数据识别名称和数量，并与已放置方块区分。受伤、死亡与重生作为实际事件进入 NPC 记忆；动作回执附带最新生命、饥饿状态和实际背包变化。因死亡中断一轮思考不记作模型服务故障。

主世界收到确认的原生时钟后，观察与当前状态摘要提供 `dayPhase=day/night`，并保留 `timeOfDay`。未知时钟和其他维度省略该字段。当前昼夜覆盖旧聊天和计划中的时间判断，白天也不表示树荫下或附近的敌对生物已经消失。

自身 `locomotion` 提供原生水体接触、熔岩接触与着地状态；`oxygen` 仅从该 NPC 自身的呼吸元数据读取，采用原生 0–20 刻度（不是剩余秒数）。未知值省略，零氧保留，不使用可能被其他实体更新的全局 `bot.oxygenLevel`。死亡与重生清除旧身体的读数，也不由接触水体推断头部是否能换气。

浮水姿态默认关闭，必须由 NPC 明确选择 `posture(mode=tread_water)`，默认持续 60 秒、最多 120 秒，续期也须再次选择。身体空闲包括模型思考期间；实际动作取得身体锁时暂停，原生操作收尾后才恢复。姿态只使用普通跳跃输入，不改变位置、速度、氧气或选择方向，不保证浮出水面或上岸；到期、显式停止、死亡、重生、断连均清除授权，重启不恢复。它补足下水后思考期间的按键持续能力，水域寻路仍未接入陆地 `travel/approach`。

单次钓鱼由 NPC 选择眼位十格内、已加载且可见的水方块，使用背包中的真实鱼竿；准备和等待默认三十秒、最多四十五秒，随后等待有界收尾。当前 Mineflayer 4.39.0 的 `bot.fish()` 没有取消接口，且会认领等待期间出现的第一个浮标，因此适配器使用原生装备、转向和物品右键，单独跟踪 Java 1.21.4 服务端标明属于该 NPC 的鱼钩及其咬钩状态。超时或取消也须处理已抛出的钩，收尾结束前保留身体锁；无法确认时停止该连接后续钓鱼。确认收线后，还可在六秒总收尾预算内观察最多一点五秒的真实库存事件，避免回执早于正常飞向角色的掉落物；取消、死亡或断连会终止这段可选等待。抛竿、咬钩、收线、鱼钩消失与实际入包分别记录，附近其他拾取造成的背包增量不能直接归因为钓获。该动作不选择水域路线、不制作鱼竿，也不自动连续钓鱼。

食用动作不会只凭原生 `consume()` 返回就声称吃掉物品。适配器等待本次使用收尾和服务器队列，再用自身使用完成状态、实际物品减少及食物对应的饥饿更新确认结果；附加状态等待最多一秒，不等待回血。换手导致原生调用提前返回时，回执保留未确认状态。停止使用采用本次操作的显式幂等收尾，不依赖可能被其他实体状态包清除的本地 `usingHeldItem` 标记；取消后仍须排空原生调用，才释放身体锁。

世界在模型思考期间继续运行。适配器向当前 NPC 发送自身受伤事件，NPC 层合并通知并重新判断；首次受伤会阻止此前排定的身体动作。收到新伤害信息后的响应有一次有限的身体执行机会，避免连续受击时永远无法行动；新的伤害不会无限延长这一机会。停止身体与取消整轮思考分开处理，尚未结束的 Mineflayer 操作继续持有动作锁，不能保证所有底层操作都能瞬时中断。

若新伤害发生在模型生成回复期间，回复中首个短移动、转向或近战动作可在原生当前状态校验下获得最多 2 秒执行窗口，避免一律多等一轮推理。移动包括 `goto`、`travel`、`approach`；较长路线也必须在此窗口结束时停止，并保留实际部分移动。该候选在回复完成时固定；回复排队后再次受伤会撤销这一许可，同批后续旧动作也不能借用。采集、合成等资源批处理仍须等待新伤情进入下一轮响应。此窗口只使用普通行动预算，不代表模型已经读到伤情，也不解锁额外行动、工具或模型轮数。`toolTrace.generationHurtWindow` 记录实际使用情况；死亡、重生、断连和总时限仍立即取消。

已实际接收伤情后，NPC 若明确选择一段 `attack`，该次攻击按其请求时长执行（最多 10 秒），不再因后续普通受击一律在两秒处截断；生成期间尚未接收伤情的旧决策仍受上段两秒限制。近战的总时限覆盖追近、瞄准、冷却与挥击，最多三次接近、累计移动 16 格，始终重验同一目标、视线、手持物与三格攻击距离。核心只为原生截止后的收尾留 100 毫秒余量，反复受击不续期，死亡和取消立即终止。`toolTrace.informedAttackWindow` 记录该许可；动作结束后仍须消化期间的新伤情，后续旧动作不能借用。目标消失或挥击发送不证明击杀。

普通决策任务限制为 6 次行动、8 轮模型调用和 90 秒。若新伤情恰好在预算边界到达，可额外提供最多一轮读取伤情的模型响应，以及一次由 NPC 自选的身体动作；说话、扫描、配方和记忆查询不能使用该额度。额度不会因连续受伤、动作失败或取消而补充，总时限、死亡和取消仍然生效。诊断中的 `emergencyBudget` 分别记录实际使用的额外动作和模型轮数。

每次模型请求与工具回执都提供当前 `executionBudget`，思考时间也计入剩余时间。对请求至少十秒的单次钓鱼，如果本轮不足以容纳请求时长和六秒收尾余量，核心返回 `deferred/time_budget`，不下发身体、不消耗行动或紧急额度，并正常结束该轮。未执行的意图只作备注保留，原目标与计划继续存在；下一轮必须结合新观察自行决定，不自动重放。运行与诊断记录 `budgetYield`，这种交接不记作世界行动失败。短动作、浮水授权时长和耗时未知的采集不会按最大耗时一概拒绝，九十秒上限与伤情、死亡取消仍生效。

任务结束后仍有真实生命下降事件待处理时，调度冷却为 250 毫秒，避免一律按普通事件等待 4 秒；实际启动仍受轮询、事件合并、角色是否存活和身体锁约束，250 毫秒不是端到端反应承诺。闲置时连续受伤不会反复推迟首个唤醒时间。模型失败退避及 NPC 互相聊天不加速的规则保留。

记忆层保存最近几轮的实际位移、资源变化、方块修改、查询指纹与失败。多轮查询无新信息时提示角色检查自己的假设，保留角色对下一步的选择；不会自动覆盖其目标或指定资源路线。

角色可用 `remember` 保存目标的 `active`、`completed`、`abandoned` 状态和自己提出的可观察完成条件。选择新目标会替换当前目标；计划关联当前目标，目标修订或结束后不自动恢复旧计划。旧格式记忆按写入顺序兼容，完整历史只追加，仍可主动回忆。这里的完成状态仅是角色对自身打算的判断，不是世界通关结果。

自动上下文和独立目标审议还保留最近三次目标结束或替换的简短记录，最新在前。它们标为历史意图，覆盖更旧的“尚未完成”审议理由；不会恢复旧计划，也不会把本人判断升格为世界事实。历史来自已有追加记录的只读投影，不新增虚构经历；当前实际身体与背包仍优先。

每约三个已结束的决策任务，NPC 会进行一次独立的简短目标审议，查看远期目标、实际资产、近期净变化、原有打算及听到的同伴原话。它自己选择继续、完成、放弃或替换局部目标；替换必须提出可观察的完成条件。审议不执行身体动作，也不规定资源路线或分工，避免把持续增加同一种物资当成永远值得继续的目标。

审议最多两轮模型调用、15 秒，包含在原任务 90 秒内，使用该 NPC 当前配置的模型；其费用计入总 usage，审议轮数另外记录。周期检查点落盘，重启不重复消费同一周期，失败后回到原执行循环。近期受伤或重生时暂缓；审议中新受伤只取消审议，伤情保留给执行 Agent。旧建议在取消后不继续写入；已开始的磁盘写入可能留下部分意图，诊断会明确标记，不能假装回滚或宣称完整应用。审议后重新观察再行动。

执行回顾单列最近几轮死亡次数、首末实际背包净变化和观察到的背包减少，避免零星拾取掩盖反复死亡。减少可能来自合成、转移或丢失，不自动推断原因；未确认库存不按空包计算。当前身体摘要单独保留空间，后续观察和回执继续覆盖它，避免把死亡前的装备误当现有装备。

`gather` 会优先选择当前可直接挖的目标，否则用 `approach` 接近已经选中的可见资源；回执保留尝试过的目标与失败原因。`approach` 的目标可以是 32 格内当前可见方块的整数格坐标，或当前可见实体 ID。它寻找符合真实交互范围的落脚点，不要求 NPC 手工计算资源旁的站位；不会自动采集、攻击、放置或替角色决定下一项资源目标。实体失去视线后停止接近，不更新隐藏位置。普通实体按近战/交互距离接近；掉落物则要求水平距离不超过 1 格、处于近身高度，避免停在够得着交互却捡不到物品的位置。`reached` 仅表示身体到达距离条件，不确认目标物品已入包；拾取延迟、背包空间和服务器判定仍会影响结果。

`approach` 复用已固定版本 `mineflayer-pathfinder 2.4.5` 的纯路线规划器，并用现有原生移动控制逐段执行。规划可以读取初始位置 32 格内已加载的碰撞几何，这比 NPC 只看到当前可见对象的观察接口范围更宽；不向 NPC 返回地图、隐藏资源或完整路线。没有加载插件的运动控制器，不调用其坐标/速度修正。未知格不当作空气，不自动挖路、垫方块、游泳或跑酷。单次接近限时 12 秒，受节点、读取、路线长度和重规划次数限制，复杂地形仍可能失败。

`travel(x,z)` 复用相同的纯规划器和原生身体，目标水平距离最多 32 格；NPC 不必先知道目的地的 Y，也不必先看到那里有某种资源。身体寻找符合目标区域的可站立高度，实际落地、停稳且水平距离不超过 1.25 格才报告到达。仍限时 12 秒，只使用已加载碰撞几何，未知格不当空气；回执报告真实终点和部分位移，不透露尚未到达的目的地高度。它不能自动开凿出口或替 NPC 选择探索方向。

`travel` 和 `approach` 开始规划时若因跳跃或击退短暂离地，会松开控制、累计等待最多一秒自然落地，然后从实际落点规划。等待计入原动作时限，不修改位置或速度；持续离地仍报错，取消、目标变化与实体失去视线会提前结束。回执中的 `planning.groundingWaitMs` 记录实际等待时间。

`goto` 保留脚部坐标契约：先尝试原生直行，遇到可恢复的障碍时，有限搜索当前眼位可见的局部落脚点绕行。每次规划半径 4 格，总计最多 8 次规划、12 段绕行、24 格拟执行段距离，整个动作限时 12 秒；不开路或垫方块。选择已看到的交互对象时，`approach` 可以省去手工计算其旁边脚部坐标的步骤。

每段移动继续经过原生碰撞与落地检查，接近原目的地后松开移动控制，等待实际落地、同层位置和惯性停稳，再确认到达；不会把部分移动、跳跃途中或另一个楼层当作成功。失败保留具体障碍与停止原因，`segmentDisplacementSum` 仅是各段起终点位移之和，不是完整行走路程。这些工具仍没有全局寻路能力。

直接挖掘和组合采集共用眼位到方块中心的保守 4.5 格范围检查，同时要求方块可见、可挖；避免用脚部距离误拒头顶可及的木头。

直接 `dig` 的成功表示目标方块已改变，另行报告当时手持物品和原版工具采集条件 `harvestEligible`；条件未知时为 `null`。它不把破坏、掉落和拾取混为一谈，入包仍以实际背包变化为准。近战保留已经发送的挥击次数与最后可见目标状态，即使后续目标离开范围、被遮挡或动作取消，也不丢弃部分执行记录；挥击次数不证明命中。完整实体方块的放置格与自身身体重叠时，会提前返回具体原因；不把火把、台阶等非完整方块一律当作占满整格。

`dig` 的失败回执区分超距、未加载、视线未知、被遮挡、确认已空和不可挖。超距判断只使用请求坐标；目标被遮挡或视线未知时不报告方块名称。空格必须经过已加载且无遮挡的视线确认，避免把重复挖空格误解释为路线失败。

`goto` 如果发现目标身体空间与当前可见方块相交，会直接报告 `target_blocked`，避免向石墙内部反复绕路；未知或遮挡的目的地仍按原有范围探索。正常地形失败、任务中断与导航超时分别说明，已经发生的部分移动和原始障碍保留在回执中。

放置先在可取消的边界内转向实际附着面，发送前重新检查空位、支撑、身体占位、手持物、视线和距离，再使用已安装 Mineflayer 的 `_placeBlockWithOptions` 跳过内部转向。避免角色在转头时死亡，旧请求却在重生后继续发送。已发送的请求仍等待服务器回复与清理完成才释放动作锁；不支持这一原生入口的版本会明确报错。

放置时短暂潜行，避免点击工作台、熔炉等支撑面变成打开窗口；当前眼位和预计潜行眼位都必须通过距离与视线检查。取消会立即释放潜行输入，原有潜行状态只在同一实体、有效连接且未取消时恢复。当前 Mineflayer 在 1.21.4 误用新输入包，本地兼容插件补发该版本要求的潜行状态包，开始与清除输入均经过同一路径，不修改依赖源码。放箱遵循原版潜行放置语义：相邻箱子默认保持独立，当前接口不承诺自动合并双箱。

`dig` 允许 NPC 明确选择自己的脚下支撑，移除后由原版物理结算下落；它不会推断下方安全、透视寻找落点或替角色选择路线。`gather` 自动选块时仍避开脚下承重，避免组合动作擅自决定这种风险。近距离移动的前向检查止于目标格，下降时容忍短暂的落地状态延迟，仍须实际到达才报成功。

合成先用 Mineflayer 原生窗口同步取得基线，并等待同一连接随后请求的服务器统计响应，避免把较早的库存包当作本次操作结束。每批确认后核对配方增减、合成格和光标，再决定是否继续；工作台合成也经过这一检查。当前兼容边界针对 Mineflayer 4.39.0／Minecraft 1.21.4。

同步失败或任务取消时不会自动重发合成；未确认的差异放在 `unconfirmedInventoryDelta`，回执带 `inventoryConfirmed=false`，NPC 不把它记作实际收益或消耗。背包储存格减少也不自动表示物品丢失，合成格和光标内的物品另行列出。有遗留材料时保留现场并停止，尚无自动清理能力。同步超时的连接停止接受后续合成，需重新连接，避免迟到回包确认新请求。已发送的原生操作完成前继续持有身体锁。

普通 `interact` 可能打开熔炉等界面，发送操作不代表窗口已经到达。适配器等待服务器处理完该交互及初始窗口内容，再收起无人管理的界面；合成、容器与熔炉动作各自持有自己的窗口，操作结束或取消后也须完成关闭及玩家背包同步。普通开门、拉杆等不弹窗操作不要求出现窗口。同步失败的连接会隔离库存操作；后续观察、记忆、界面与进度判定也把背包标为未知，不能把缓存物品再次当作事实。重新连接前仍可感知世界和执行不依赖库存的动作。

普通方块与实体交互在原生转向完成后、真正构造点击包时再次检查取消、目标、距离、视线和手持物品。此适配针对已固定的 Mineflayer 4.39.0 调用顺序，只包装本次参数，不更改客户端发包方法或永久替换 Bot 方法；用实际安装的原生插件回归验证异步转向和取消竞态。已经发出的操作仍等待窗口与同步收尾，不能通过取消撤销服务器已经接受的点击。

放置确认检查指定格的真实变化，并兼容普通、灵魂、红石火把各自的墙上形态。侧面附着还须由当前注册表确认对应物品、方块与掉落关系；不能仅凭物品名和新方块名不同就报失败，也不能把任意同掉落方块都算作成功。原本已有的方块、未变化的空气或错误变体不会成为本次放置的成功证据。

容器开启期间，物品数量从当前窗口的玩家储存区域读取；关闭后才回到普通背包。熔炉取出产物和容器取物的计数不会再读取尚未更新的旧背包。相关回归使用实际安装的 Mineflayer 库存与熔炉插件验证。

这些动作不替角色编排“伐木→石器→铁器→下界”的固定流程。显示在控制台的资源、铁锭、下界、末地等里程碑只是已发生事件的记录，不向角色注入预定分工。

`say` 采用本地听觉：NPC 只能收到同维度、三维距离 16 格内已加载玩家的普通消息，高差计入距离。NPC 还可以显式选择 `broadcast` 使用原版全服聊天，以 `[世界] ` 标记发送最多 240 字的单行正文；原生客户端玩家也可输入这个标记来选择世界频道。只有服务器实际送来的聊天事件才进入接收者记忆，世界频道不要求发言者实体已加载或处于同一维度，不自动附加坐标、背包、目标或其他私人信息。损坏、空白、过长的频道消息整条忽略，普通 `say` 不能借保留标记冒用频道。

观察与说话回执都带 `communication`；`sent=true` 只表示发出，`deliveryConfirmed=false` 表示没有确认收件人收到，不能用发送成功推断同伴答应分工或收到物品。广播和近处交谈都作为 `hearsay` 保存，记忆保留广播来源，不能把远程消息当作同伴在附近的证据。广播占普通行动额度，不使用受伤后的额外身体行动机会；收到其他 NPC 的广播不会打断当前任务或加快正常调度。物资交接仍须实际接近并核对背包变化。

`scan.name` 是不区分大小写的名称子串过滤，`log` 可以匹配 `oak_log`；`animal`、`food` 不会自动展开为语义类别。扫描回执保留实际查询和过滤方式，省略 `name` 可查看不同可见对象。字面查询为空不能推断所有动物、食物或目标资源都不存在。扫描和采集都不返回被遮挡候选的数量或其是否耗尽内部预算；`searchIncomplete=true` 保守表示未证明整个半径已覆盖。

普通观察和扫描还保留已可见方块的少量原生 `properties`，例如门框 `eye`、流体 `level`、炉子 `lit`、门 `open` 与作物 `age`。`false` 和 `0` 是有效状态；字段缺失表示未提供，不推断为关闭、未填眼或水源。投影只在可见性检查之后读取该方块本身，使用字段白名单及最多八项、256 字节预算，不读取 NBT、容器内容或隐藏邻居。这为 NPC 判断点击效果提供当前观察，不自动填框、寻找要塞或改变资源路线。

当前身体动作仍通过 Mineflayer 原生能力执行，接近对象的路线计算使用 Pathfinder；未加载其运动控制器、Collectblock 或自动战斗插件。移动能力仍有限；随机复杂地形、远距离探索和长期规划需要实测检验，不能因为接口接通就视为已经能完成全流程。发生执行问题时修复工具，不用传送或发物资绕过问题。

## 只读比较模型决策

可冻结同一角色的当前观察和记忆，比较不同模型的第一条回复：

```powershell
node --env-file-if-exists=.env scripts/minecraft/compare-decisions.ts Sheldon gpt-6-luna gpt-6.1-sol
```

脚本只读取游戏 API，在 `var/minecraft/decision-comparisons/` 写入隔离的记忆副本、输入和结果，不执行任何建议动作。它复用已配置的 CLIProxyAPI 兼容接口；一次相同或不同的动作建议不能证明模型的完整生存能力。实际通关仍以运行中的世界为准。

## 单个角色的实景模型试用

可以在本地 `.env` 中为单个 NPC 覆盖模型 ID，例如 `ANIMA_MC_MODEL_HUYIFEI=gpt-6.1-sol`；其他三人继续使用 `ANIMA_MODEL`。配置名称取角色名的大写形式，移除覆盖即可恢复默认。变更后正常保存并重启服务，继续同一存档。每次任务独立选择模型，不通过修改共享环境变量切换并发请求。

覆盖复用原来的接口、协议和密钥，模型必须由该提供方支持。目前试用通过已验证工具调用的本机 CLIProxyAPI 兼容接口；不应将这一结果推定为官方 Chat Completions 对该模型的支持。官方 GPT-6.1 Sol 工具调用要求 Responses，模型选择应依据代表性任务的成功率与耗时，见 [OpenAI Docs 部署检查](https://developers.openai.com/api/docs/guides/deployment-checklist#choose-a-model-for-the-workload)。

每轮诊断记录实际 `model`、`turns`、`actions`、`usage` 和 `durationMs`。任务耗时包含模型、工具和世界等待，不等于单次推理延迟；未配置价格时不从零值成本推断免费。观察重点是实际保有资源、死亡、无效动作、食物与协作成果。不同角色同处一个持续变化的世界，且共同执行器修正会影响所有人，因此这一试用用于判断是否值得继续，不作为严格的模型性能排名。
