# NPC 服务

服务的组装入口：连接 NPC 核心、pi 运行适配和桥接层，管理角色实例、事件唤醒、任务调度和生命周期。

当前实现一个世界接入前的文字会客室。五个角色可切换、流式回复、查看人格档案、开始新对话；已经结束的对话会留在本地，每个浏览器会话与角色分别存储。

## 启动

在 Anima 根目录运行 `npm run chat`，打开 <http://127.0.0.1:18790>。默认仅绑定 `127.0.0.1`。

模型配置优先使用 `.env` 中的 `ANIMA_*`（也兼容教学示例的 `PI_EXAMPLE_*`）。没有显式密钥时，读取 `~/.pi/agent/models.json` 和 `auth.json` 中的 API key 配置，不修改它们，也不把密钥发送给浏览器。本地自定义 provider 目前支持 `openai-completions`；内置 provider 可通过环境变量选择。完整模型名按上游接口实际可用的名称填写。

这是真实 API 聊天，没有离线固定回复兜底。缺少配置、调用失败、输出截断或中断会明确失败，失败轮次不会写入角色记忆。

资料位于 `data/roles/<id>/`：

```text
role.json             身份、来源版本、校验值与材料数量
corpus.jsonl          保留说话人及来源索引的对话窗口
analysis-sample.json  分散选取的最多 48 个分析样本
profile.json         模型生成的人格、事实记忆、中文场景注释与局限（默认分析约 24 个样本）
persona.md           可读的人格档案
self.md              可读的来源事实与关系
SKILL.md             便于阅读／移植的档案组合；不会作为宿主工具指令执行
```

`npm run roles:prepare` 会下载缺失的固定版本素材，校验 SHA-256，已有角色材料不覆盖。`npm run roles:build` 调用模型逐个生成档案，已有 `profile.json` 跳过。遇到生成失败可重跑 build，继续尚未完成的人物。人物初稿参考 yourself-skill 的五层行为档案结构，并附证据 ID；不是把所有台词交给模型完整阅读过，也不是微调模型。

## 对话过程

NPC 核心使用 BM25 对台词和中文场景注释检索。初始上下文由人物档案、来源事实、匹配片段及当前会话最近完整轮次构成。pi-agent-core 可调用 `recall_character` 再查询本角色的材料；英文角色的工具说明要求提供英文检索关键词。

当前是轻量关键词检索，中文注释只覆盖抽样场景，跨语言语义召回尚不完整。后续可以替换为 embedding 与重排，无需更换角色目录或聊天界面。

会话数据保存在 `var/role-chat/sessions/`。已提交记录成对写入；中止或失败不会保留半轮。上下文取最近完整轮次，较早记录按本轮关键词检索补充；这属于基础的对话记忆，不是完整的长期记忆提炼系统。每个角色只收到属于自己的当前用户会话，角色切换不会共享聊天记录。

用户界面明确标注 AI 模拟。原作人物设定、统一世界身份与当前用户的聊天关系分别处理；当前不运行世界事件、自动群聊或复杂社会规则。模型无法观察用户外表或周围环境，福尔摩斯的推理只能依据对话提供的事实。

## 验证与边界

运行 `npm run test:roles` 检查角色／会话隔离、双语检索注释、完整轮次裁剪、pi 工具循环、取消和推理标签过滤。测试模型只用于测试文件，服务入口始终使用真实配置。

人格质量仍需通过真实聊天修订。熟悉影视作品的基础模型可能自行补充已有知识，不能将聊天效果全部归因于档案。试验材料与衍生档案留在本地忽略目录，开源代码提供处理与运行流程。
